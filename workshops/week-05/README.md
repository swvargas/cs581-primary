# Workshop 5 — Three-Framework Incident Analysis

This workshop runs against a real incident on the plant, not a paper scenario. Read
`scenario.md` first, then look at your own system's SIEM history.

Deliverables, per the Canvas assignment:

- `workshops/week-05/three-framework-analysis.json` — the schema is stubbed in this folder;
  fill it. Retrieve notification timing live from NRC regulations, not from memory.
- `workshops/week-05/coordinator-narrative.md` — one page; prompts are in the file.
- `workshops/week-05/session-log.md`

Secondary repo: `role-analyses/week-05/synthesis.md` — NRC Security Inspector vs. IAEA
Safeguards Inspector.

Shared: the "W5 Incident Timeline" discussion in Canvas. Post what your system saw; read what
the other owners saw. You cannot complete the clock and coordination fields from your own
system alone, by design.

Handover record, not a graded Workshop 5 deliverable: the runbook for the system you
inherited lives on the host, and you continue its change log there. When W5 is due, commit
the current host copy to `workshops/week-05/RUNBOOK.md` so your repo shows the system as you
received and ran it during the incident. It is graded as part of the handover, not under the
Workshop 5 rubric.

The Canvas assignment is authoritative on content, structure, and points. If this README and
the assignment disagree, the assignment wins and tell me so I can fix this file.

Note: an older template left a file named `regulatory-compliance-map.md` in some repos. It is
not a Workshop 5 deliverable. Leave it or delete it; it is not graded.
